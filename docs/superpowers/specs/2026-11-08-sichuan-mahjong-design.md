# 四川麻将（血战到底）网页单机版 设计

## 意图

一个能在手机横屏上打的四川麻将网页游戏，规则对齐用户线下和朋友打的版本。四个座位都通过同一个玩家接口接入：第一版是 1 个人类 + 3 个规则 AI，之后要能把任意座位换成 LLM 玩家（包括四个座位全是 AI 的观战局），而不改引擎。

## 目标

- 完整打完一局血战到底，计分正确，可以连续打下一局，总分在本次页面会话内累计
- 引擎与 UI 完全分离：引擎是纯 TS，能在无 DOM 环境（bun 脚本）里跑完整局
- 统一的异步玩家接口，人类、规则 AI、未来的 LLM 都是它的实现
- 手机横屏可玩，触控友好；桌面浏览器也能玩

## 非目标

- 换三张
- 联机、账号、持久化存储、音效
- 3D
- LLM 玩家本身（只预留接口）
- AI 难度系数（规则 AI 预留一个参数位即可，不做多档）
- 规则设置界面（规则参数放在配置对象里，改代码即可）
- 番型只做下文列出的这些：不做带幺九、将对、门清、中张、天胡、地胡；不做过水不胡、呼叫转移

## 反目标

- 引擎 import 任何 UI / Vue 代码
- 引擎接受不在合法动作列表里的动作
- 规则 AI 的出牌节奏让人类等得不耐烦，或快到看不清发生了什么

## 技术约束

- Vite + TypeScript + Vue 3，包管理用 bun
- 2D 渲染，DOM/CSS 即可
- 牌面素材：`FluffyStuff/riichi-mahjong-tiles`（CC0），只取 `Regular/` 下的 `Man1-9`、`Sou1-9`、`Pin1-9`、`Front`、`Back`，不要 `-Dora` 变体和字牌。牌面 SVG 只有图案，需要叠在 `Front.svg` 之上显示。素材复制进仓库
- 玩具项目，不写单元测试；判胡、算番、整局流程用仓库外的一次性脚本验证（见"验证"）

## 代码结构

```
src/
  engine/   纯 TS：牌、牌墙、判胡、算番、牌局状态机、结算
  players/  Player 接口的实现：HumanPlayer、RuleBotPlayer
  ui/       Vue 组件，只读引擎状态、把点击转成动作
```

座位由一个配置决定（例如 `seats = [human, bot, bot, bot]`），换座位类型只改这里。

## 规则

### 牌与座位

- 108 张：万(m)、条(s)、筒(p) 各 1–9，每种 4 张
- 座位 0 在屏幕下方（人类），按出牌顺序 0→1→2→3 依次是 下、右、上、左
- 第一局庄家随机；之后由上一局第一个胡牌的人坐庄；上一局无人胡则庄家不变
- 庄家起手 14 张，其余 13 张；牌从牌墙前端摸，杠后补牌从牌墙尾端摸；两端共用同一堆剩余牌，剩余为 0 即牌墙耗尽

### 定缺

发完牌后四家同时选一门作为缺门（引擎并发询问四个座位，全部回答后统一公开）。之后：

- 手里有缺门牌时，只能打缺门牌
- 缺门牌不能碰、不能杠（含暗杠、补杠）
- 手里有缺门牌不能胡

### 行牌

- 当前玩家摸一张后，可以：自摸胡、暗杠、补杠、或打出一张
- 杠（任何一种）后从尾端补摸一张，然后同样可以胡、再杠或打牌
- 有人打出一张牌后，其他未胡玩家可以声明：胡、碰（手里有 2 张）、明杠（手里有 3 张）、过
  - 引擎并发询问所有有可选动作的玩家，全部回答后按优先级裁决：胡 > 杠/碰 > 过
  - 多人同时胡（一炮多响）全部成立；有人胡时，这张牌上的碰/杠作废
  - 碰之后该玩家打一张，然后从他的下家继续；明杠之后补摸再继续
  - 点炮被胡后，从"按出牌顺序离点炮者最远的那位胡牌者"的下一位未胡玩家继续摸牌
- 补杠时，其他玩家若能胡这张牌，可以抢杠胡（同样并发询问）；被抢则补杠不成立，不收杠钱，该牌归胡牌者。暗杠不能被抢
- 不能吃

### 胡牌

- 牌型：4 组面子（顺子或刻子，碰/杠算刻子）+ 1 对将；或 7 个对子（七对，只能门清，即没有碰杠）。七对中允许出现 4 张相同的牌，算 2 个对子
- 手牌（含胡的那张）不能有缺门牌
- 胡牌者亮出手牌并离场，之后不再摸牌、打牌、付钱或收钱（已发生的结算保留）

### 结束

三家胡牌，或牌墙耗尽且最后一张牌引发的动作处理完毕，本局结束。牌墙耗尽时仍未胡的玩家进入流局结算。

### 番型（加法叠加）

| 项 | 番 |
|---|---|
| 平胡 | 0 |
| 对对胡（4 组都是刻子） | +1 |
| 七对 | +2 |
| 清一色 | +2 |
| 金钩钓（碰杠后手里只剩 1 张单吊胡） | +1 |
| 根（4 张同样的牌都在自己手牌+碰杠里，每有一种） | +1 |
| 自摸 | +1 |
| 杠上开花（杠后补牌自摸） | +1 |
| 杠上炮（杠后打出的牌被胡） | +1 |
| 抢杠胡 | +1 |
| 海底捞月（摸到牌墙最后一张自摸） | +1 |

由叠加自然得到：清对 = 3，龙七对 = 七对 + 1 根 = 3，清七对 = 4，清龙七对 = 5。

封顶默认 4 番。一次胡牌的单家支付 = 底分 × 2^min(番, 封顶)，底分默认 1。

### 胡牌支付

- 点炮：只有点炮者付给胡牌者；一炮多响时点炮者分别付给每个胡牌者
- 自摸：每个仍未胡的其他玩家各付一份

### 刮风下雨（杠钱即时结算）

- 明杠：打出那张牌的人付 2 × 底分
- 补杠：每个仍未胡的其他玩家付 1 × 底分
- 暗杠：每个仍未胡的其他玩家付 2 × 底分

### 流局结算（牌墙耗尽时仍未胡的玩家之间）

1. 查花猪：手里还有缺门牌的是花猪，付给每个未胡且不是花猪的玩家 底分 × 2^封顶
2. 查大叫：不是花猪且没听牌的玩家，付给每个听牌的未胡玩家，金额按该听牌玩家可能胡的最大番（只算牌型番和根，不算自摸、杠上开花等情景番），受封顶限制
3. 退杠钱：没听牌的玩家（含花猪）退还本局从刮风下雨收到的全部杠钱，原路退给当时付钱的人

### 配置项

底分、封顶番数、AI 思考延迟，集中在一个规则配置对象里。

## 玩家接口

引擎在需要某个座位做决定时，调用该座位的玩家对象：

- 输入：该座位视角的局面（PlayerView）+ 当前所有合法动作列表
- 输出：异步返回列表中的一个动作
- 引擎只接受列表中的动作，收到列表外的动作直接抛错（fail-fast；LLM 的重试/兜底由未来的 LLM 玩家实现自己负责）
- 另有一个可选的事件回调，引擎每产生一个公开事件就通知所有座位（UI 和 LLM 都需要）

PlayerView 只包含该座位能合法看到的信息：

- 自己的手牌（区分刚摸到的那张）
- 所有人的碰杠（暗杠对他人只显示为暗杠，不显示是哪张）、牌河、定缺（公开后）、是否已胡及胡的牌、当前分数
- 其他人的手牌张数
- 牌墙剩余张数、庄家、当前轮到谁
- 本局公开事件日志（谁摸牌、打了什么、碰杠胡、结算），供 LLM 构建上下文

动作类型：定缺(花色)、打牌(牌)、自摸胡/点炮胡/抢杠胡、碰、明杠、暗杠(牌)、补杠(牌)、过。

## 规则 AI（RuleBotPlayer）

优先级规则 + 同分随机，目标是"像个正常牌友"，不追求强：

- 定缺：选张数最少的一门
- 能胡就胡
- 打牌：有缺门牌先打缺门；否则按启发式评分打最没用的牌（孤张、边张优先，靠近顺子/对子的保留），同分随机
- 碰/杠：不拆坏已有搭子时就碰/杠，否则过
- 保留一个难度参数位（第一版只有一档）
- 每次决定前延迟一段时间（默认约 0.6s），让人类看清过程

## 界面

横屏单页。竖屏时全屏提示"请横屏"。

- 布局：人类在下，三家 AI 在左、上、右；中央是四家牌河和牌墙剩余数
- 每个座位旁显示：分数、缺门标记、庄家标记、已胡标记
- 人类手牌：大尺寸，按花色排序，刚摸的牌与手牌隔开一点；点一下选中（抬起），再点一下打出，防误触。不可打出的牌（有缺门时的非缺门牌）变暗
- AI 手牌显示牌背；胡牌后亮出
- 有可选动作时，在手牌上方弹出大按钮：胡 / 碰 / 杠 / 过；暗杠、补杠有多个选择时让人类选牌
- 定缺阶段弹出三个花色按钮
- 碰、杠、胡等事件在对应座位附近短暂飘字
- 本局结束弹出结算面板：逐条列出每笔支付（谁付谁、多少、番型明细），各家本局得分与累计分，"下一局"按钮

## 验证（仓库外一次性脚本）

- 判胡：一批手写牌型（普通胡、七对、龙七对、清一色、对对胡、金钩钓、带缺门、差一张）结果正确
- 算番：上述牌型 + 情景番的番数与表一致，封顶生效
- 听牌：查大叫用到的"听哪些牌、最大番"在几个典型手牌上正确
- 整局：四个 RuleBot 无头跑 1000 局不抛错，每局所有支付之和为 0，每局结束条件正确
- UI：在浏览器里按手机横屏尺寸打完一局并截图
